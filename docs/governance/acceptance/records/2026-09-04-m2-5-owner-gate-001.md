# M2.5 Traceability Verification Snapshot Acceptance Candidate Record

## Scope

**WHY**

M2.3 fixed the Release Issue set, and M2.4 fixed the three typed Edge Revision categories. The M2.5 candidate must prove that the system can deterministically generate auditable and replayable Fixed and Included results, fixed `Verified=false`, and exact Gaps using only those historical facts and Locked Manifest authority, and that it can recover from failure without rewriting history.

**WHAT**

- The V11 Migration, asynchronous Verification Run, fixed Input Ledger, Worker, immutable Snapshot, read/replay API, and Task 7 performance, recovery, Gate, CI, and operations specification at current English Subject Commit `a1a86715d244965061e5d333ca04e26f92a5dc79` and paired Chinese Subject Commit `2652c7f442b84a6ed04865e0104bf01a6c45e69d`.
- Pilot performance and constant query-count verification using 20 Issues and 2,000 fixed Edges.
- A PostgreSQL `pg_dump` restored through `pg_restore` into an independent PostgreSQL instance, followed by recomputation of the Snapshot canonical digest from restored relational facts; a strictly newer `pg_postmaster_start_time()` proves a real restart of the independent database before fresh reconnect/repository reclamation of a RUNNING job; poison Dead Letter and a new-Run manual retry are also covered.
- A fixed 12-step fail-closed Gate, Evidence exact-property allowlist and secret/absolute-path rejection, summary/digest, and read-only GitHub Actions Artifact.

**BOUNDARY**

- The V0.1 Core Contract, Release-centric architecture, Locked Manifest authority, Evidence, Traceability, Deterministic Quality Engine, Adapter/Plugin, and ADR governance are unchanged.
- M2.5 does not read Jira, GitHub, CI, Device, Test Agent, or a Company environment; it does not produce `Verified=true` or reconstruct history from the latest Revision, JSON, files, or cache.
- This candidate does not authorize Company, a real Provider, M3, a `main`/`release` merge, Tag, release, or production deployment.
- The relaxed shared-CI performance hard limits only detect regression; they are neither a Company performance commitment nor Company Ready evidence.
