## Implementation and reuse

Added `scripts/demo/run-quality.ps1`, `scripts/demo/quality-demo.mjs`, and `demo/quality/config.example.json`; follow the [runbook](../../demo/quality-evaluation-runbook.md). Each of four scenarios POSTs a new Test Run under the same Release, waits for a formal terminal state, submits Evaluation, and retains its exact 202 ID. History pagination selects only that ID, never another successful record. A failed session preserves idempotency keys, returned Run/Evaluation IDs, and progress, explicitly becomes FAILED, and never automatically retries, cancels, or overwrites history.

Existing APIs, exporter, and renderer are reused directly. findQualityEvaluation is extracted from the exporter for polling/export reuse, preserving existing missing/duplicate/cross-Release/pagination-loop errors. Existing verifyEvidenceLocator is moved to the shared export validator so the fixture and entry reuse metadata checks and error codes, without a second source or permission implementation. Existing Node orchestration meets this slice's responsibilities without another QualityDemoScenario.kt, Backend service, or workflow.

Configuration strictly limits loopback origin, environment variable name, fresh output directory, timeouts, and four-scenario formal references. The Test Run request shape reuses OpenAPI CreateTestRunRequest. Token enters only the Authorization header and is not saved in configuration/reports/diagnostics. Redirects are rejected; responses are bounded to 16 MiB, HTTP to 10 seconds, and each scenario to 600 seconds. Configuration accepts no command, executor, existing Run/Evaluation ID, or plaintext credential. The entry does not deploy Backend, prepare sources, publish rules, start an Agent or real Provider, invoke adb, or download Payload.

In addition to formal action/error, the four scenarios check pinned Case PASS/FAIL facts. requiredIssueBlock requires Case PASS and a fact matching an exact requiredIssueRefs entry with required=true and verified=false. This checks demo prerequisites without becoming a second rule interpreter. Report provenance remains UNKNOWN; local configuration assertions do not prove real/synthetic source classification.

verifyEvidenceMetadata explicitly controls metadata access separately from pure reporting. Fixed references and current VERIFIED observations are retained in evidence-access.json with payloadDownloaded=false. Unrequested checks and unpinned input are recorded as NOT_REQUESTED / NOT_PINNED. The runbook explains server integrity-observation side effects of metadata GET and separate download authorization. TDR-026 bytes/transaction window semantics remain unchanged.
